# Meeting Feature Plan Template

Keep the final plan concise but implementation-ready.

## Outcome

State the user-visible result and defaults inferred from the request.

## Current path

- Existing render/component path
- State owner and settings/permissions
- Realtime path, only when relevant
- SafeMeet extension seam

## Implementation

For each step:

1. Name exact files or directories.
2. Describe behavior, not just edits.
3. State whether it is SafeMeet-only or an upstream integration point.
4. Mention role, responsive, RTL, and failure states that affect the step.

## Performance and compatibility

- Existing infrastructure reused
- Network/write/render behavior
- Upstream conflict classification: low, medium, or high

## Verification

- Automated commands/tests
- Manual role/device/state matrix
- Clear acceptance criteria

Exclude speculative future work. Do not include unresolved questions in a final plan.
